# Правила разработки ER-Studio

## Начало каждой задачи

Рабочая директория агента — корень этого репозитория (рядом с README.md). Редактируемый проект Construct — `game/project.c3proj`; MCP получает абсолютный путь к `game/`, а не к корню и не к `.c3p`. Сначала прочитать `docs/STATUS.md`, `docs/CONCEPT.md`, `docs/ARCHITECTURE.md`, `docs/WORKFLOW.md`. Затем соответствующие задаче OBJECTS.md, ASSETS.md, CAMERA.md, TESTING.md и ROADMAP.md. Задача пользователя определяет scope; не реализовывать весь roadmap автоматически. При нехватке контекста продолжать по STATUS, не выдумывать выполненные проверки.

В этой копии нет персональной зависимости от старых путей автора. Вне репозитория защищены исходная A_Spoonful_for_Grandma и recovered; не изменять их. Старая mcp_trial — источник первоначального импорта, не вторая ветка разработки. Не синхронизировать копии автоматически. Подагентов без явного запроса пользователя не запускать.

## Ограничения и архитектура

Это настоящий проект Construct 3 Free, целевая исходная версия r506.3. Не подменять движок Canvas/HTML-игрой, не обходить ограничения. Два слоя World/UI; игровые механики — модульный JavaScript с официальным Scripting API. Не расходовать события без необходимости. Сверять новые API с официальной документацией. Сейчас один рецепт и одна кастрюля. Книгу рецептов и инвентарь разрабатывать только отдельной согласованной задачей.

Структуру объектов/анимаций/Layout редактировать исправленным MCP по docs/MCP_SETUP.md. Скрипты — обычным редактором. Если MCP не поддерживает операцию, описать ограничение; минимальная нативная JSON-правка допустима после резервной копии, сравнения с рабочим форматом и проверки. Не передавать PNG base64 в контекст: читать и отправлять через код. Не запускать bridge/CDP/сетевой preview без отдельной задачи.

## Установка MCP агентом

Сначала проверить наличие и путь уже установленного исправленного сервера, не переустанавливать без причины. Если установки нет, прочитать MCP_SETUP.md, сообщить пользователю о клонировании закреплённого исходника, npm-зависимостях, сборке и проектной конфигурации, получить разрешение. Разрешение прошлого разработчика не действует на новом компьютере. При явном разрешении в текущей задаче повторно не спрашивать. После разрешения выполнить tools/setup/install-mcp.ps1 -ApproveInstall; конфиг клиента создавать только когда это входит в разрешение, параметром -WriteCodexConfig. Глобальные настройки, доверие к папкам, политики исполнения и credentials без необходимости не менять. Установка не означает подключение к агенту: проверить доступные инструменты, чтение структуры и validate_project. Если клиенту нужен перезапуск/доверие, назвать точное действие и не заявлять подключение до проверки. MCP-тест на изменениях выполнять в отдельной копии .local, не в game/.

## Безопасное изменение

Перед игровыми правками сделать git status, проверить текущую ветку/чужие изменения, сохранить коммит/резервную копию в .local/backups. Не перезаписывать незакоммиченную работу другого человека. Закрыть проект Construct перед дисковыми правками, затем открыть заново: несохранённый редактор может перезаписать диск. Один владелец Layout/спрайта в одной задаче; не редактировать те же JSON одновременно. Не удалять невидимые объекты без анализа назначения.

Запрещено программно переставлять/дорисовывать/обрезать части тела бабушки. Новые варианты — цельные фигуры; разрешены целокадровая нарезка, выравнивание/масштаб целого кадра, штатное зеркалирование. Сохранять рабочие направления и оригиналы. PNG из game/images используются движком, не являются мусором.

## Обязательный учёт в том же изменении

- Любая игровая правка: обновить STATUS.md (факт, проверки, ограничения, следующий шаг) и CHANGELOG.md; указать автора/ветку/дату и связанный Issue/PR, если есть.
- Создание/удаление/переименование/перенос/изменение назначения объектов: сразу обновить docs/OBJECTS.md. Отдельные разделы сцен/слоёв, точные имена, все UID, назначение, видимость, скрипты и инструкция ручного редактирования. Скриптовые связи тоже актуализировать.
- Графика/анимации: обновить ASSETS.md (`npm run assets` строит техническую таблицу), ASSET_SOURCES.md и пояснения DESIGNER.md при необходимости. Фиксировать активные/архивные анимации, Origin и зеркало.
- Новый модуль/изменение связей: ARCHITECTURE.md. Важное новое решение: DECISIONS.md. Изменение очереди: ROADMAP.md. Неполная задача: оставить запись handoff по шаблону docs/templates/HANDOFF.md.
- Выполнить npm run check, npm test; при структуре также MCP validate_project. Проверить ограничения слоёв, файлы и collisionPoly всех кадров. Добавлять значимые регрессии для исправленных багов. Проверить diff и состав пакета.
- Открытие в Construct и Preview записывать отдельно с датой, версией, исполнителем и результатом. Без запуска писать «не проверено», не выдавать mocks/валидатор за запуск. Финальный ответ: что изменено, как проверено, что осталось, какой проект/коммит открывать.

CI контролирует часть учёта; он не заменяет ручную проверку смысла документации. Не выполнять формальные пустые обновления ради обхода проверки. Секреты, .codex с локальными путями, node_modules, .bak, диалоги ИИ и логи в Git/релиз не добавлять. Коммиты и PR делать по WORKFLOW; не force-push и не сливать чужие ветки без задачи.
