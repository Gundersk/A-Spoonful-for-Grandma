# Какую версию MCP использовать

**Использовать оригинальный сервер с нашим обязательным патчем. Установщик уже делает это автоматически; вручную редактировать исходники не нужно.**

## Что уже находится в GitHub

| Файл | Зачем нужен |
|---|---|
| [version.json](version.json) | Адрес оригинала, точный commit/version и SHA256 патча. Не брать latest. |
| [collision-poly.patch](collision-poly.patch) | Наше изменение исходников сервера и регрессионные тесты. |
| [../setup/install-mcp.ps1](../setup/install-mcp.ps1) | Скачивает закреплённый оригинал, применяет патч, собирает и проверяет сервер; при разрешении создаёт проектный конфиг клиента. |
| [UPSTREAM-LICENSE.txt](UPSTREAM-LICENSE.txt) | Лицензия MIT оригинального проекта. |
| [probe.mjs](probe.mjs) | Проверяет чтение/валидацию игры через реально запущенный MCP по SDK/STDIO. |

Сам полный исходник/сборка сервера и node_modules **не хранятся в репозитории игры**. Они появляются после установки в `.local/tools/construct3-mcp/`. Эта папка исключена из Git и игрового пакета. Поэтому обычный clone игры ещё не означает установленный MCP.

## Единственный рекомендуемый способ установки

В PowerShell из корня репозитория, где лежат AGENTS.md и package.json, после разрешения пользователя:

```powershell
.\tools\setup\install-mcp.ps1 -ApproveInstall -WriteCodexConfig
npm run mcp:check
```

Нужны Git и Node.js22+ с npm. Параметр -ApproveInstall подтверждает установку; -WriteCodexConfig — создание локального проектного конфига. Агент на новом компьютере сначала запрашивает соответствующее разрешение; разрешение прежнего разработчика не переносится. При существующем другом конфиге установщик его не перезаписывает.

Результат: **уже исправленный, собранный сервер**, полученный воспроизводимо из оригинала и патча. После этого при необходимости перезапустить клиент, открыть корень репозитория, разрешить доверие папке и проверить, что агент видит инструменты. SDK-проверка не доказывает нативное подключение к конкретному чату. Сервер получает абсолютный путь к `game/`, где находится project.c3proj.

## Что именно исправлено

Оригинал: [liauw-media/construct3-mcp](https://github.com/liauw-media/construct3-mcp), v1.10.0, [закреплённый commit](https://github.com/liauw-media/construct3-mcp/tree/1eb4973e0d032fba794c719b1e3971cf71e188a3).

Шаблон Sprite/TiledBg создавал пустой collisionPoly.points=[], а валидатор его пропускал. Construct падал при открытии Sprite с ошибкой must have at least three points in a collision poly. Наш патч создаёт прямоугольник [0,0,1,0,1,1,0,1] и добавляет проверку корректности явных полигонов во всех кадрах. Импорт PNG и неправильные полигоны покрыты регрессиями. Это исправление известного дефекта, а не гарантия отсутствия других ошибок сервера или успешного Preview.

Установщик проверяет контрольную сумму патча и точный upstream commit, применяет патч, выполняет сборку и три тестовых файла (на текущей версии135 тестов). Эти действия уже проверены с нуля и повторным запуском. Для проверки после установки: `npm run mcp:check`; затем отдельная ручная проверка в Construct при игровых изменениях.

Не клонировать произвольный latest вместо этой схемы; не копировать старую локальную папку с машинными путями. При обновлении версии менять version.json/патч совместно и заново проверять исправление. Отдельный fork сейчас не требуется: он создал бы ещё одну версию для синхронизации. Полная инструкция, ручная установка, другие клиенты и откат — [docs/MCP_SETUP.md](../../docs/MCP_SETUP.md).
