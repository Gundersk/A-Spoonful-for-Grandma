## 1. Данные предметов и инвентарь — запланировано

Основы уже согласованы в INVENTORY_DESIGN: не обсуждать заново жёсткий лимит/Tab/колесо/категории/подсветку/единственное местоположение. ## 2. Инструменты и один цикл — запланировано

После модели выбора: ложка набирает крупу и переносит в стоящую кастрюлю, сохранены0.1/1.0/10ложек; варежка допускает горячий подъём и блокирует wheel до постановки. Уточнить температуру/операции/визуал ложки и поведение при броске до кода. Не добавлять урон/износ/навыки. Сохранить текущую баллистику и единственный источник состояния. Сценарий и границы — TOOLS_AND_INTERACTIONS.

## 3. Минимальная книга — запланировано

Согласованы граф, модульный UI, итоговая карточка, независимые показатели, вложенный рецепт с возвратом. Подготовить фон/элементы из референсов отдельной арт-задачей (непрозрачные атласы не готовы). Уточнить клавишу книги, финальную раскладку и минимальный объём интерактивности. Первый срез — данные существующей гречки, без автоматической смены игровой экономики/введения соусов. Информационный UI книги может идти параллельно модели предметов, если нет одновременной правки тех же game/файлов; интеракции/эксперименты зависят от модели рецептов.

База5, соль×1.1, группы соусов/мяса и пример82.5 — предварительный баланс для книги, не поручение поменять100вккал прототипа. Сначала согласовать порцию, значения пользы/вреда, группы/пустой выбор, условия открытия/известности/доступа и глубину навигации. Потом отдельные задачи графа, экспериментального открытия, а позднее сохранения прогресса. См. RECIPE_BOOK_DESIGN.

Порядок1–3 отражает зависимости и рекомендуемый маленький объём задач, не утверждённые сроки. Новые функции реализуются только по отдельной карточке YouGile и запросу; текущая задача — только документация.
