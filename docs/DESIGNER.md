# Работа с графикой

Дизайнер и программист работают в одном репозитории. `game/images/` — настоящие игровые PNG Construct, связанные с кадрами через objectTypes. `art/sources/` — отобранные исходники; `art/proposals/` — предложения, не импортируемые автоматически. Технический каталог: ASSETS.md; происхождение/приоритеты: ASSET_SOURCES.md; позиции на сцене: OBJECTS.md.

## Предложить вариант без Git

Основная задача/обсуждение — карточка YouGile. При необходимости технического вложения в GitHub можно открыть Issues → New issue → «Ассет или замена графики» со ссылкой на карточку YouGile. Указать предмет/имя объекта, приложить PNG с прозрачностью и превью, при необходимости исходник архивом. Написать, что заменяется и почему, размеры/состояния/готовность. Статус в заголовке или описании: Предложено → На обсуждении → Утверждено → Внедрено. Прикреплённый в Issue файл до интеграции не является частью игровых исходников. Скачивание/доступ зависят от доступа к private-репозиторию.

## Предложить через Git

Ветка `art/<предмет>`; папка art/proposals/<предмет>-<вариант>/ с PNG, preview.png и README по шаблону. Загрузить через Git или GitHub Add file в свою ветку, затем PR. Не заменять game/images без согласованной интеграции: изменение размера/Origin может повлиять на постановку и коллизии.

## Требования

Уютный пиксельный стиль, насыщенная тёплая кухня, согласованные перспектива/свет/масштаб. Прозрачный фон у отдельных предметов. Полный кадр с полями, без обрезанных ног/рук. Не переписывать рабочие бабушкины направления склейкой частей тела. Для боковой/диагональной ходьбы одна сторона и зеркало в движке; кадры должны показывать реальный обмен опорной ноги, не подпрыгивание корпуса. Руки вверх — перенос над головой, без нарисованной кастрюли. Активные generated-анимации имеют 4 кадра 256×320, Origin(.5,.95); W↔E, SW↔SE.

Мебель, которая интерактивна, постепенно должна стать отдельными ассетами; сейчас отдельный стол уже есть, остальное преимущественно фон. Нужны базовые держатели без инструментов, инструменты отдельно (будущие покупки). Ближайший фокус — существующая гречка: маленькая кастрюля, сырая/помытая/готовая и уровни наполнения. Мешок/контейнер: полный, 2/3, 1/3, пустой — план; сейчас банка не меняет графическое наполнение. Не рисовать всю будущую кухню без задачи.

После утверждения программист импортирует через исправленный MCP, настраивает Origin/анимации/размеры, проверяет в Construct, обновляет реестры и отмечает внедрение в карточке YouGile и связанном техническом обсуждении со ссылкой на commit/PR. Оригинал сохраняется в art/sources с понятным именем. Для сторонних файлов указывать автора/URL/лицензию; для ИИ — происхождение и выбранный утверждённый вариант без обязательного хранения всего диалога.

## Новые допустимые референсы владельца

[ASSET_REFERENCES](ASSET_REFERENCES.md) и art/references содержат11файлов от владельца, не финальные предложения дизайнера. Четыре UI инвентаря — альтернативы; конкретные количества/12/32 не ограничивают согласованный безлимитный инвентарь. Книга — старый раскрытый фон и отдельные интерактивные элементы, цветочные углы свободны. Макет страницы использует устаревший огонь: будущие вккал обозначать сердцем. Польза и вред отдельны, шкалы программные. Непрозрачные атласы/карточки требуют подготовки; JPG/JFIF не даёт прозрачности, простая нарезка PNG тоже не убирает его непрозрачный фон. Связь numbered-atlas↔TXT22 сохранена. Каталог источников игры ASSETS не означает, что новые референсы уже внедрены.

Мешок — один предложенный рисунок, не полный набор полного/2⁄3/1⁄3/пустого. Лист кастрюль содержит10картинок, возможное соответствие стадиям предварительное; перед заменой утвердить размеры/Origin/стадии/уровни. Ничего из этого не заменять в game/ без отдельной арт-интеграции.

По данным владельца графика генерировалась с gpt6 и nano banana2.1, в обоих случаях уровень рассуждений «высокий». Точные названия, статус этих сведений и отличие от фактического инструмента конкретного файла — AI_WORKFLOW.md. Не объявлять все PNG результатом одной модели без сведений об источнике.
