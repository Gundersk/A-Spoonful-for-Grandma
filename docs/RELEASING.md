# Выпуск минипрототипа

1. В чистой согласованной ветке выполнить npm run check, npm test и MCP validation при доступном сервере.
2. Выполнить `py -3 tools/packaging/package.py --version 0.1.0` (или python3). В dist появятся папка с OneMoreSpoon.c3p/README/SHA256SUMS и внешний zip для преподавателя. Пакет формируется только из нативных game/файлов; инструкции ИИ, MCP, исходники art, концепт и node_modules не включаются.
3. Открыть **именно упакованный** .c3p в Construct, запустить Preview, пройти TESTING.md. Записать commit, исполнителя, версию редактора и результаты. Сейчас эта проверка не подтверждена: первый архив помечен кандидатом. Если изменяется код — пересобрать и проверить снова.
4. При успехе обновить STATUS/TESTING/CHANGELOG, снять отметку кандидата в шаблоне пакета (tools/packaging/package.py) с сохранением фактической записи приёмки. Сделать commit. Создать тег `prototype-0.1.0` на проверенном commit (`git tag -a prototype-0.1.0 -m "Учебный минипрототип"`, `git push origin prototype-0.1.0`). Не ставить тег «проверено» до Preview.
5. GitHub → Releases → Draft a new release → выбрать тег. Приложить внешний zip и при желании c3p. В описании — реализованное, управление, ограничения и версия Construct. Private Release виден только участникам с доступом; преподавателю без GitHub передать внешний zip через учебную систему/облако.

Первый импорт можно получить через Code → Download ZIP как исходники команды, но это не чистый пакет сдачи. Возможность web/export Free Edition в этом этапе не проверена; автономный exe/публичная игра не обещаны. Вход GitHub/системные настройки не включать в архив.

## Push, main и Release — разные версии

- Commit/push обновляет исходники конкретной ветки, но не main при открытом PR.
- MergePR обновляет main, но не файлы уже опубликованного Release.
- Release/tag и приложенные .c3p/ZIP — отдельный снимок. После исправлений собирать и загружать новый кандидат из точного commit; проверять именно скачанный пакет, а не только рабочую папку.
- Старые файлы не заменять незаметно под тем же тегом: выпускать следующую версию и обновлять STATUS. В README пакета указан source commit; его сверять с release notes.
