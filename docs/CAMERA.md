# Камера

Два режима CameraController: static — фиксированная точка; follow — прямое следование за PlayerBody с ограничением по границам Layout. При меньшей локации камера центрируется по соответствующей оси. Размер области просмотра берётся из World.getViewport(), поэтому границы не зависят от жёстко заданного размера экрана. Без дополнительного сглаживания/зума.

Kitchen остаётся static (480,270). Единственная реальная сцена — Kitchen; огород не добавлен. Конфигурация CAMERA_LAYOUTS находится в scripts/camera.js. Пример будущей записи: Garden: { mode: 'follow' }. Неизвестные сцены по умолчанию статические с центром Layout. Цель задаётся callback, сейчас main.js возвращает player.body. При будущих переходах нужно переинициализировать игровую логику и цель для новой сцены: сейчас весь игровой bootstrap рассчитан на одну кухню. Сам модуль читает runtime.layout при каждом update.

UI остаётся на существующем втором слое: независимая прокрутка (480,270), соответствующая текущему дизайну HUD 960×540. Модуль предполагает существование слоёв World/UI. Если сменится дизайн интерфейса или появится зум, адаптировать UI отдельно. Существующий API Mouse использует World/UI и не требует ручного вычитания прокрутки. Другие источники прокрутки, например ScrollTo behaviour, одновременно не включать.

Проверка в Construct: открыть проект, убедиться в прежнем полном виде кухни, пройтись по комнате и проверить неподвижность фона/UI. Follow проверять на временной копии: увеличить Layout, поставить mode:'follow', снять/перенести ограничивающие перемещение стены и пройти по локации; у краёв камера должна остановиться, HUD остаться на экране. Размер фона и размещение мира при этом отдельная задача. Изменять рабочую кухню ради демонстрации режима не нужно.

Автоматические тесты проверяют контроллер с имитацией официального API; это не запуск Construct. Preview обоих режимов агентом не проверен.
