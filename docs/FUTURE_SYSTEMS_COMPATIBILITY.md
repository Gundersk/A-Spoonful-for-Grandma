# Совместимость будущих систем

Это анализ требований и возможные точки расширения, **не реализованная архитектура новых систем**. Никаких новых файлов game/, классов инвентаря/ложки/книги сейчас нет. Утверждённые игровые принципы — INVENTORY_DESIGN, TOOLS_AND_INTERACTIONS, RECIPE_BOOK_DESIGN; ниже технические следствия для дальнейшей задачи.

| Существующая часть | Что есть сейчас | Что учитывать при будущей реализации |
|---|---|---|
| KitchenState/state.js | Одна pot, её location/content/spoons/remaining/served; числовые запасы | Расширять единственный источник истины и операции перемещения. Не заводить отдельную копию кастрюли в UI/инвентаре. Индивидуальность предметов при нескольких кастрюлях должна сохраняться; точный формат идентификаторов ещё не выбран. |
| Interactions | E/Q, ближайшая станция, canReachPot, текущая крупа в руках | Ложка потребует операции источник→содержимое ложки→стоящая кастрюля. Граница допуска инструмента и выбор подходящего предмета проверяются перед изменением состояния; не вызывать старый pantry-act параллельно новой логике. |
| ThrowController | GroundXY+Z, поверхность, дальность220, возврат и содержимое | Переносить тот же экземпляр/запись через hands/flight/surface. При будущем инвентаре исключить двойное место; момент горячей блокировки при flight требует решения. Не менять текущую баллистику ради UI. |
| input.js/main.js | Tab не опрашивается, wheel нет; ЛКМ бросает по координатам World вне двух HUD-панелей | Новый UI должен маршрутизировать ввод и захватывать свои клики, иначе клик по книге может бросить кастрюлю. Это будущая обязательная интеграционная проверка, не готовый input-router. Поведение паузы/модальных окон не задано. |
| hud.js, World/UI | Текстовые показатели и PotVisual; два слоя | Расширяемый UI строить отдельными элементами на существующем UI, не через новый слой/статичную картинку всего окна. Категории/граф/шкалы — из данных; никакой новой сцены на каждый рецепт. |
| data.js/economy.js | Один рецепт и действующая пропорциональная награда | Каталог будущих рецептов/групп должен быть расширяемым. Новый граф5×множители — отдельный предварительный дизайн; миграция баланса отдельно согласуется, не меняет сегодняшний RECIPE. |
| camera.js | Static Kitchen, follow с clamp; main bootstrap одной кухни | Для будущих больших сцен применять режим камеры; переходы/пересоздание цели ещё отдельная задача. В текущей кухне камера не меняется. |

Технически требования совместимы с нынешними модулями, но не сводятся к добавлению картинок: нужна согласованная миграция одной pot к нескольким физическим предметам и модель инструментов. Горячесть не равна content=ready, selected не равен location, выбранная карточка не равна discovered. Предлагать отдельные модули данных/представления/прогресса при реализации; их точные имена сейчас не утверждены.

Минимальные будущие регрессии: кастрюля в одном месте; быстрый слот не клонирует предмет; Tab/колесо и UI-клик не конфликтуют с E/Q/ЛКМ; горячую можно взять только с защитой и wheel блокируется до постановки; перенос/бросок не теряет содержимое; ложка уменьшает запас и увеличивает наполненность один раз; книга различает неизвестность/доступ/выбор, сохраняет выбор при возврате. Точные действия для открытых вопросов согласуются до написания тестов, не изобретаются тестами.
