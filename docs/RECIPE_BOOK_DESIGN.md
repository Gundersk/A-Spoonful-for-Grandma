# Книга рецептов и открытия

Основная концепция книги **согласована**, реализация **запланирована**. Граф гречки/числа и подробности открытий **предварительно согласованы**. В game/ этих систем нет. Реальная награда прототипа сейчас до100 вккал за10ложек; значения ниже не заменяют её в этой задаче.

## Согласованная структура

Интерактивная книга показывает блюда, ингредиенты, последовательности приготовления, модификации и характеристики **разветвлённым графом**, а не только обычным списком. Игрок может свободно экспериментировать с ещё не записанными сочетаниями. Отображение строится из данных рецептов, не из отдельной вручную собранной сцены для каждого блюда.

Вид — раскрытая старая книга, тёплые страницы, цветочный декор, пиксельная графика. Допустим единый фон раскрытой книги. Карточки/изображения блюд и ингредиентов, стрелки/связи, названия, категории/вкладки, кнопки выбора, закрытия/возврата, показатели/шкалы и переходы к вложенным рецептам — независимые интерактивные элементы. Не впекать содержимое всей страницы в один PNG. Угловые цветы должны оставаться свободными от основных элементов.

## Предварительный граф гречки

| Узел или группа | Предварительное значение | Выбор |
|---|---:|---|
| Простая гречка | 5вккал | База |
| Соль | ×1.1 | Необязательная модификация |
| Соусы/добавки: майонез, кетчуп, кабачковая икра | ×3, ×2.5, ×2 | Один вариант внутри этой группы |
| Мясное дополнение: котлета, сарделька | ×5, ×5 | Один вариант внутри этой группы |

Пример:5×1.1×3×5=82.5вккал (гречка+соль+майонез+котлета). Три соуса×два мясных дополнения дают шесть основных сочетаний при выборе из обеих групп, не считая соли/без соли. Это не запрет других экспериментов. Гуляш и новые группы — будущие расширения через данные. Правила отсутствия выбора в отдельных группах и пересчёт порций требуют уточнения.

Все эти числа — **предварительный баланс книги**, не окончательная экономика и не действующие параметры RECIPE/economy.js. Текущий прототип:1ложка→10вккал/1монета;10ложек→100/10. Не смешивать шкалы и не корректировать код автоматически. Связь будущих5вккал с размером порции/10ложками **не определена**.

## Итоговая карточка и характеристики

Предусмотрена одна динамическая итоговая карточка вместо одновременного вывода всех полноразмерных комбинаций. Выбор меняет изображение блюда (из подготовленных вариантов), название, вккал, полезность, вредность. Модель допускает расширение групп из данных.

Вккал — число и **сердце**, не огонь. Полезность — зелёная шкала и лист. Вредность — отдельная янтарная/оранжевая шкала. Не объединять пользу/вред в одну шкалу со знаком. Наполнение шкал задаёт программа, не неизменный рисунок. Расчёт пользы/вреда по ингредиентам и сочетанию — предварительная концепция; значения/формулы/диапазоны шкал не определены.

В [макете гречки](../art/references/recipe-book/buckwheat-page.png) ещё нарисован огонь — это расхождение референса, использовать согласованное сердце. Числа/заполнение шкал макета не становятся правилами.

## Вложенные рецепты

Котлета, кабачковая икра, будущий гуляш могут сами быть приготовленными блюдами. Предусмотрена кнопка раскрытой книги для перехода на отдельную страницу рецепта компонента. Возврат сохраняет предыдущий выбор. Глубина и точные правила вложенности/циклических связей **не определены**; книга не должна автоматически открывать неизвестную комбинацию из-за известности её компонентов.

## Прогресс открытий

Поддержанная, **предварительно согласованная** концепция: впервые успешно приготовленное новое сочетание открывает соответствующий рецепт для просмотра. Знание гречки с кетчупом и котлеты по отдельности не открывает автоматически их комбинацию. Возможны вопросительные знаки и ненавязчивые подсказки без раскрытия всего решения. Базовая гречка известна с начала; возможна стартовая подсказка о соли. Полные сохранения/разблокировки сейчас не реализуются, но открытия позже входят в сохраняемый прогресс.

| Что различать | Смысл |
|---|---|
| Неизвестный рецепт | Ещё не обнаружен |
| Известный, закрытый прогрессом | Информация известна, доступ ограничен условиями, которые ещё надо определить |
| Открытый | Известен и доступен |
| Выбранная карточка | Состояние UI поверх открытого рецепта, а не отдельное открытие |

Визуальный ориентир: обычная карточка — открыта; золотая — открытая сейчас выбрана; серая — неизвестна. Не смешивать selected с discovered/unlocked. Отдельный вид известного, но закрытого прогрессом рецепта ещё не задан.
