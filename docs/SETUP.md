# Разворачивание проекта

## Получить исходники

Нужны Git и доступ к репозиторию. Для private-репозитория владелец приглашает GitHub-аккаунт участника; авторизация выполняется через Git Credential Manager/обычный вход GitHub, пароли в чат не передаются.

```powershell
git clone https://github.com/Gundersk/A-Spoonful-for-Grandma.git
cd A-Spoonful-for-Grandma
git status
```

Пример новой локальной папки: `C:\Projects\A-Spoonful-for-Grandma`. Путь можно выбрать другой. Все дальнейшие команды — **из корня репозитория**, не из game/scripts. Открыть именно этот корень в Codex/редакторе ИИ. Он найдёт AGENTS.md. Сам Construct открывает `game/`.

## Construct 3 и версия проекта

Рабочая базовая редакция команды — **Construct3 Free, r506.3**. В game/project.c3proj записано savedWithRelease=50603. Это версия исходного проекта, не обещание, что всякая более новая/старая сборка полностью совместима. Повторяемая проверка начинается с r506.3; переход на другую версию согласовывается отдельно, на копии, с последующей записью версии/проверок в STATUS/TESTING.

Обязательного отдельного установщика нет: Construct работает в браузере. Для конкретной версии откройте [официальную страницу r506.3](https://www.construct.net/en/make-games/releases/stable/r506-3), нажмите **Launch r506.3**, затем проверьте номер в **Menu → About / О программе**. Общий адрес [editor.construct.net](https://editor.construct.net/) может открыть актуальную версию, поэтому одного URL недостаточно для фиксации release. Если выбранная версия недоступна или открылась другая, не сохраняйте поверх командной копии до согласования.

На Windows можно использовать браузерный редактор или установить его как приложение/PWA: открыть редактор, выбрать **Install as app / Установить как приложение** в меню Construct либо соответствующий пункт установки приложения в Chrome/Edge. Это удобная оболочка веб-редактора, а не другой движок. Отдельная установка MCP при этом не происходит. Официальное описание: [Get Construct](https://www.construct.net/en/make-games/manuals/construct-3/getting-started/get-construct-3). Не скачивать сторонний «инсталлятор Construct».

Для папочного проекта используйте поддерживающий доступ к локальным файлам браузер (на рабочем месте применялся Edge; официальная инструкция приводит Chrome). Откройте **Menu → Project → Open → Project folder / Открыть папку проекта** (название зависит от локализации), выберите всю папку `game/` с project.c3proj и разрешите доступ. Если команды нет, проверьте поддержку браузера; запасной путь — .c3p ниже. Для нашей разработки: World/UI, не более двух слоёв, модульный JS, пустой Bootstrap. Не использовать недоступные возможности/обход ограничений. Отдельные npm/Node/MCP для обычного Preview не требуются.

## Игра без инструментов разработчика

После открытия game/ запустите Preview кнопкой редактора и пройдите TESTING.md. Проект открывайте из нужной ветки/коммита: push в ветку, main и загруженный Release — разные снимки. Если редактор уже держал проект до внешних правок, переоткройте его; не сохраняйте старое состояние поверх диска.

Если доступно только открытие файла, используйте опубликованный `.c3p` или соберите кандидат из корня:

```powershell
py -3 tools/packaging/package.py --version 0.1.0
```

Нужен Python3 (стандартная библиотека; на macOS/Linux `python3`). Результат — dist/OneMoreSpoon_0.1.0/OneMoreSpoon.c3p. Для одного запуска можно открыть архив через **Open local file**. Для разработки сохраняйте папочный проект: **Save as → Project folder** в отдельную пустую папку, затем осознанно перенесите нужные изменения в game/. Не сохранять игру прямо в корень репозитория вместо game/ и не вести конкурирующие копии. [Официальная инструкция файлов и папок](https://www.construct.net/en/make-games/manuals/construct-3/overview/saving-projects).

## Для программиста

Установите Node.js 22+ (проверено на 24.13.0) с npm и Git. Установка самой игры не требует npm-зависимостей. Выполните `npm run check` и `npm test`. Для структурных правок установите MCP по [MCP_SETUP](MCP_SETUP.md). Его SDK не нужен игровому runtime. Любой запуск игр в Construct проверяется отдельно от этих команд.

Перед правками закройте открытую копию в Construct; после внешних изменений откройте заново. Если редактор предлагает сохранить старую версию поверх диска, отмените сохранение и сначала разберитесь с расхождением.

Профиль агентной разработки и сведения о моделях графики: [AI_WORKFLOW](AI_WORKFLOW.md).

## Начать работу с ИИ

Откройте корень репозитория как папку проекта в локальном клиенте агента. Начальный запрос:

> Прочитай AGENTS.md и документы в указанном им порядке. Сообщи актуальное состояние и точный путь редактируемого Construct-проекта. Проверь подключение исправленного MCP. Если нужна установка, сначала запроси разрешение. Затем возьми согласованную задачу из STATUS/карточки YouGile, сохрани текущую игру и веди документацию в том же изменении.

Если ИИ-клиент не читает AGENTS автоматически, явно приложите его. Нельзя гарантировать соблюдение инструкций любым клиентом; PR и CI добавляют контроль. Полный порядок сдачи задачи — WORKFLOW.md.

## Обновиться и продолжить на другом ПК

В чистой рабочей папке: `git switch main`, `git pull --ff-only`, прочитать STATUS/CHANGELOG, выполнить проверки. При переносе незавершённой работы сначала отправить её ветку и HANDOFF, затем на другом ПК получить ветку. .local/.codex не переносить: setup заново создаст абсолютные пути. История Git/документы переносимы; доверие к папке и вход GitHub задаются локально.

## GitHub для человека и его агента

Пошаговая настройка Collaborator → свой GitHub/GCM → свой ИИ-клиент → ветка/commit/push/PR: [GIT_AGENT_ACCESS](GIT_AGENT_ACCESS.md). Для локального агента отдельный аккаунт ИИ в GitHub и коннектор ChatGPT не обязательны; обычная Git-авторизация независима от входа OpenAI. Облачный Codex требует отдельного подключения репозитория/окружения. Вывод токенов/общие credentials не нужны.
