# Использованные модели и передача работы ИИ

По данным владельца проекта01.11.2026:

| Работа | Название модели / режим, указанные владельцем |
|---|---|
| Агентная разработка/программирование | **gpt 6.1 sol**, уровень рассуждений **medium** |
| Генерация графики | **gpt 6**, уровень рассуждений **«высокий»** |
| Дополнительная генерация графики | **nano banana 2.1**, уровень рассуждений **«высокий»** |

Это сведения о процессе команды, не требование к запуску игры и не проверенные API-идентификаторы/гарантия доступности конкретного переключателя в любом клиенте. Не переименовывать модели по догадке. В этой задаче модели не устанавливались/не переключались, новая графика не генерировалась. Для каждого старого PNG соответствие конкретной модели не установлено: не приписывать архиву или всем art/sources одну модель автоматически. Фактические записи built-in imagegen в прежних источниках сохраняются.

Разработчик открывает корень репозитория в агентном клиенте, читает AGENTS/STATUS/CONCEPT/ARCHITECTURE и профильный design-документ. Базовый профиль разработки для воспроизведения рабочего процесса — указанная владельцем агентная модель с medium, если она доступна. Выбор другой модели фиксировать в handoff/PR при необходимости; никакой ИИ не заменяет Preview/ревью.

Установка исправленного MCP — MCP_SETUP.md, отдельно от выбора модели и установки Construct. На новом ПК нужна разрешённая установка Git/npm/сервера/конфига. Наличие MCP/модели не доказывает подключение инструментов к чату. Секреты/API-ключи в репозиторий не добавлять. Для игры ИИ-клиент и MCP не нужны.

Дизайнер сохраняет одобренный исходник/промпт и указывает фактически использованный инструмент/модель/режим, если известны. Предложения владельца не выдавать за готовые работы дизайнера. Сейчас архив — art/references, не art/sources действующих игровых кадров. Работа начинается с карточки YouGile; GitHub PR/commit ссылается на её URL/ID. Содержимое документов и реестров обновляется по AGENTS вместе с изменениями; открытые вопросы не заполняются выдуманными правилами.

## Доступ к Git отдельно от модели

[GIT_AGENT_ACCESS](GIT_AGENT_ACCESS.md) описывает настройку локального и облачного вариантов. Участник входит собственными аккаунтами; отдельный бот не требуется. Модель/подписка, локальный GitHub-вход, право записи в репозиторий и MCP — независимы. Автоматическое ведение документов/commit/push выполняется запущенным агентом в рамках разрешённой задачи, а не одним подключением GitHub.
