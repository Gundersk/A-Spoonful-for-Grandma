# Установка исправленного Construct MCP

Сервер редактирует папку Construct по STDIO. Это инструмент разработчика, не часть игры. Исходник [liauw-media/construct3-mcp](https://github.com/liauw-media/construct3-mcp), v1.10.0, commit `1eb4973e0d032fba794c719b1e3971cf71e188a3`. Наш патч tools/mcp/collision-poly.patch обязателен. Не устанавливать `latest` вместо закреплённой версии.

## Разрешение и установка

На новом ПК агент сначала объясняет установку и получает разрешение на Git/npm/сборку и проектный конфиг. Команда ниже означает явное разрешение этих действий; автоматическое изменение глобальной конфигурации и выдача доверия папкам в неё не входят. Скрипт не устанавливает Node/Git: если их нет, он останавливается.

Из корня репозитория в PowerShell:

```powershell
.\tools\setup\install-mcp.ps1 -ApproveInstall -WriteCodexConfig
```

При блокировке локального скрипта можно запустить отдельный процесс `pwsh -NoProfile -ExecutionPolicy Bypass -File .\tools\setup\install-mcp.ps1 -ApproveInstall -WriteCodexConfig`. Это не меняет глобальную политику Windows. Если pwsh отсутствует, используйте доступный PowerShell и проверьте его сообщения. Запуск этого скрипта проверен при подготовке на Windows/PowerShell 7; macOS/Linux — ручной способ ниже.

Скрипт клонирует исходник в `.local/tools/construct3-mcp`, проверяет commit, применяет патч, выполняет `npm ci --ignore-scripts`, явную сборку и тесты исправления. Создаёт `.local/mcp-install.json` и, при указанном параметре, проектный `.codex/config.toml` с абсолютными путями node/dist/game. Уже существующий чужой config не перезаписывает. Повторный запуск проверяет commit/патч и пересобирает; npm ci выполняется, если зависимостей ещё нет. .local/.codex исключены из Git.

## Подключение к Codex

Откройте **корень этого репозитория** в локальном Codex. После создания конфигурации перезапустите/перезагрузите клиент, если он не перечитал MCP. Если клиент запрашивает доверие проекту — подтвердить должен пользователь. Проектные конфиги загружаются только для доверенных проектов: [официальная документация конфигурации](https://learn.chatgpt.com/docs/config-file/config-basic), [MCP](https://learn.chatgpt.com/docs/extend/mcp).

Проверьте наличие сервера construct3 и инструментов `get_project_summary`, `list_layouts`, `validate_project`. Эти имена проверены по фактическому списку 83 инструментов закреплённой версии. Наличие файлов конфигурации не доказывает подключение. В клиенте попросите агента прочитать структуру game/ и выполнить validate_project. Если инструменты в текущем чате не появились, сообщить это честно; локальная SDK-проверка ниже подтверждает сервер, но не доступность его инструментов агенту.

```powershell
npm run mcp:check
```

Команда выполняет только чтение, listTools и validate_project, сохраняет краткий результат в .local/reports. SDK загружается из установленного сервера, base64 не выводится. Серверу передаётся именно game/. В этой сессии прямой нативный Construct MCP не предоставлен в каталоге агента: доступ используется через SDK/STDIO. На другом клиенте статус подключения нужно проверить заново.

## Другой клиент и ручная установка

Минимальная STDIO-конфигурация: command — абсолютный путь node; args — абсолютный путь `.local/tools/construct3-mcp/dist/index.js`, затем абсолютный путь `game/`. Шаблон JSON находится в tools/mcp/client.example.json; placeholders заменить, не копировать буквально. Формат и место конфига зависят от клиента. Не обещать подключение локального STDIO-сервера обычному облачному чату без поддержки локальных MCP.

Ручной способ (корень репозитория, Git/Node/npm уже установлены):

```text
git clone https://github.com/liauw-media/construct3-mcp.git .local/tools/construct3-mcp
git -C .local/tools/construct3-mcp checkout --detach 1eb4973e0d032fba794c719b1e3971cf71e188a3
git -C .local/tools/construct3-mcp apply --check <абсолютный-путь-к-tools/mcp/collision-poly.patch>
git -C .local/tools/construct3-mcp apply <абсолютный-путь-к-tools/mcp/collision-poly.patch>
```

Далее в папке сервера: `npm ci --ignore-scripts`, `npm run build`, `npm test -- test/tools/collision-poly.test.ts test/construct3/templates.test.ts test/construct3/integrity.test.ts`. На POSIX node для конфигурации берите из `command -v node`. PowerShell-установщик уже делает эти шаги автоматически. Лицензия исходного сервера MIT включена рядом с патчем; зависимостями управляет upstream package-lock.json.

## Что исправлено и как откатить

Шаблон create_object записывал useCollisionPoly=true и collisionPoly.points=[]; import PNG сохранял дефект, валидатор его пропускал. Construct падал: must have at least three points in a collision poly. Правильный прямоугольник: [0,0,1,0,1,1,0,1]. Патч меняет Sprite/TiledBg-шаблоны и проверяет явные полигоны во всех кадрах, включая вложенные анимации: чётное число координат >=6, конечные числа, три разные неколлинеарные точки. Пропущенный штатный default-полигон допустим. Регрессионный тест включён в патч.

MCP создаёт .bak, но надёжный откат — Git и отдельная копия перед экспериментом. Тест создания Sprite выполнять в .local/trials/<имя>/ с project.c3proj, указав именно её серверу. Открыть результат в Construct вручную; validate_project не доказывает открываемость. Изменения в game/ не переносить автоматически. npm audit ранее показывал уязвимости зависимостей; это не исправлялось сменой версий. Сервер локальный STDIO, HTTP/CDP не включаем. При обновлении upstream отдельно проверить audit/патч/тесты, не выполнять npm audit fix вслепую.

## Следующие запуски

После успешной настройки достаточно открыть репозиторий в том же клиенте, проверить целевой game/, прочитать STATUS и приступить к задаче. Переустановка не нужна при каждом чате. После переноса папки повторно сгенерировать конфиг с новыми путями (существующий конфиг сохранить/исправить осознанно).
